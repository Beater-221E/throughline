# Throughline

> 当前版本：**v1.0.0**（首个稳定版）。
>
> 给 [DeepSeek Harness](https://github.com/deepseek-ai) 用的本地跨会话记忆插件：把历史会话按「轮次」建索引，
> 让 agent 用一个工具检索自己的过去，而不是让你重复交代。

Throughline 把 DSH 的会话历史拆成对话轮次（turn）建索引，只暴露一个模型可调用的工具 `memory_search`。
当 agent 怀疑某个事实写在更早的会话里时，它会主动检索；你不需要手动维护 `AGENTS.md`，也不需要把历史
粘进上下文。所有数据留在本机：SQLite + 一个 118M 的多语向量模型，不联网、不上云。

## 特性

- **自动入库**：首次加载自动建库；之后每个新会话触发一次增量入库。当前正在进行的会话永不入库（由 DSH 管理）。
- **轮级混合检索**：中文查询默认 `0.7 · z(向量) + 0.3 · z(BM25)`，英文查询走纯向量通道（跨语言更准）；两者都可用环境变量调整；BM25 的词法通道把中文切成字符 bigram，因此中文专名与命令也能精确命中。
  结果按 token 预算装配，一次返回几千 token，而不是整段会话。
- **注入精炼**：默认 token 预算 1500；长轮次只注入命中句附近（摘录模式），相似轮次按 MMR 去重、最多返回 12 条，同样的信息花更少的 token。
- **触发策略**：系统提示明确「上次 / 之前 / 继续 / 约定 / 规则」等场景要先检索再回答。
- **规则注入**：会话开始把 `pinned.md` 直接注入系统提示，规则不依赖检索也生效；`control.json` 里 `"injectPinned": false` 可关闭。
- **设置页**：实时计数、已入库来源（点一下即可排除）、暂停/重建/清空、逐条事件提示、用量统计。
- **规则捕获**：你明确说出的长期要求（「以后…」「每次…」「记住…」）会被 agent 写入 `pinned.md`，下个会话随系统提示注入；带显式措辞的句子也会被自动抽取。设置页里只保留删除。
- **人工层**：`pinned.md` 放你希望始终优先的规则，`glossary.json` 做中英术语扩展；都是纯文本，没有编辑器界面。
- **隐私默认**：纯本地、不联网；入库前按规则脱敏凭据；可排除工作区/会话/关键词；索引可随时清空。

## 工作原理

```
会话日志 (zstd 帧)
   │  提取用户消息与助手回复文本，丢弃注入上下文、工具调用与结果
   ▼
SQLite FTS5（中文 bigram 词法）+ 向量桶（e5-small）
   │  中文 0.7 向量 + 0.3 词法，英文纯向量；按 token 预算装配
   ▼
memory_search ──► agent 上下文
```

入库由 `agent/created` 事件触发，单写者锁 + 水位线 + 120 秒最小年龄；失败两次后进入 30 分钟退避。

## 安装

要求：DSH 0.2.2-rc.5 及以上、Python 3.10+、Node 20+、约 130 MB 磁盘给模型。

```bash
# 1. Python 依赖（装到插件将使用的同一个解释器）
python -m pip install -r service/requirements.txt

# 2. 向量模型（约 129 MB，一次性）
node scripts/fetch-model.mjs

# 3. 安装 bundle（插件 → 添加插件，选择本目录）
#    或：plugin_manager install_bundle <本目录绝对路径>
```

安装后重启一次 DSH，再刷新页面。入口在 **设置 → Throughline**。

## 使用

agent 会在需要回忆过去时自行调用：

```
memory_search(query="上次定的交付检查是什么", budget_tokens=1500)
```

你也可以把长期规则写进 `storages/throughline/pinned.md`：

```markdown
- 发布检查：提交前必须运行 scripts/audit.sh --strict。
```

`glossary.json` 用于把中文术语映射到英文/同义词，只扩展词法查询，不影响向量通道：

```json
{ "压缩": ["zstd", "compression"] }
```

## 技术路线：为什么是检索，而不是沉淀

项目早期做过另一条路线：让 agent 自动把会话蒸馏成规则/知识页（类似自动维护的 `AGENTS.md`）。
在 24 个真实会话片段上量化后放弃了：

| 测量 | 结果 | 含义 |
|---|---|---|
| 继续任务时探索性 token 的重复率 | 28.8% | 看似有优化空间 |
| 其中与"记忆内容"相关的部分 | 10.8% | 其余是环境重建 |
| 重复 token 中环境重建的占比 | **89%** | 大头属于持久化 shell，不是记忆问题 |
| 错误签名在后续会话复现的比例 | **12.2%** | 错误记忆价值很低 |
| 蒸馏产物体积 | 与语料同量级 | 压缩比接近 1，写侧没有净收益 |

写侧还引入持续错误、与代码演进不同步、规则治理三类风险。所以最终只做读侧：**索引原文轮次，按需检索，不产生派生知识**。

选择轮级（turn）而不是会话级：一次提问真正需要的通常只有 1–2 轮，命中轮次前后各扩 1–2 轮（共 3–5 轮）
约 3k token，而整段会话是它的 5–10 倍。预算装配让「一次调用 ≈ 1.5k token」成为可预期成本。

## 实验记录

评测协议：固定语料，按「锚点（带稀有 token）/ 改写（中文换说法）/ 跨语言（英文问中文）」三层构造查询，
指标 nDCG@10、MRR、R@5，干预实验用配对 bootstrap（1000 次）。共两批快照：
A = 1,167 turn / 72 查询；B = 1,312 turn / 75 查询。

| # | 实验 | 设置 | 结果 | 决策 |
|---|---|---|---|---|
| 1 | 中文词法 | FTS5 默认分词 | 中文 BM25 命中恒为 0 | 必须自建词流 |
| 2 | 字符 bigram | 拉丁词 + bigram/unigram | 纯词法 nDCG 0.252 | **采用** |
| 3 | 稠密 vs 词法 vs 融合（快照 B） | e5 + BM25 | 0.258 / 0.252 / 0.275(0.3) / **0.310(0.7)** | 融合，权重可调 |
| 4 | 权重扫描 | 0.0–1.0 六档 | 见下表 | 默认 0.7 |
| 5 | 语言感知 | 不含 CJK → 稠密 1.0 | 0.310→**0.326**，跨语言 0.072→**0.117** | **采用** |
| 6 | 模型选型（快照 A） | bge-en / bge-zh / e5 | 见下表 | e5（多语） |
| 7 | 短轮次阻尼 | cos × len/40 | −0.012 [−0.029, +0.002] | 拒绝 |
| 8 | 自适应权重 | 词法命中 <3 时切稠密 | −0.001 | 拒绝 |
| 9 | 中文停用 bigram | 过滤高频双字 | ±0.000 | 拒绝 |
| 10 | 510 token 窗口 | 长轮次截断重算 | ±0.000（长金标 R@10 39/72 不变） | 拒绝 |
| 11 | 语言感知权重（早期版） | 中文查询降权 Latin | +0.014 [−0.006, +0.037] | 未采用（无把握） |
| 12 | 自动共现词表 | 语料共现挖中英对 | 总体 0.203（锚点被噪声冲垮） | 拒绝 |
| 13 | 人工术语表 | 24 条中文→英文 | 0.300→**0.367**，改写 0.379→**0.580** | **采用** |
| 14 | pinned 规则 | 每行一条，+boost | hit@3 4/6→**6/6** | **采用** |
| 15 | 交叉编码器重排 | bge-reranker-base int8，top-20 | R@1 +7pt、MRR +0.057，但 **1.8 s/查询** | 不默认 |
| 16 | 日期过滤 | 解析日期后过滤 | hit@5 1/6→2/6，名次 20→10、14→2、986→28 | 暂缓（证据弱） |
| 17 | 注入精炼 | 摘录 + MMR + 预算 1500 | 同一查询 40 条/1498 tok → **12 条/262 tok** | **采用** |
| 18 | 桶压缩 | 删除行后重写桶 | 孤儿向量：2 桶 → **1 桶 / 1.8 MB** | **采用** |

| 模型 | 体积 | 锚点 | 改写 | 跨语言 | 总体 | MRR |
|---|---|---|---|---|---|---|
| bge-small-en-v1.5 | 34 MB | 0.471 | 0.377 | 0.084 | 0.311 | 0.474 |

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 自动沉淀规则 / 自动维护 `AGENTS.md` / 蒸馏知识页 | 写侧成本高于收益（见上表），且会持续污染 |
| 纯向量检索 | 中文专名、命令、标识符精确匹配差 |
| 纯词法检索 | 改写查询全线失效 |
| Elasticsearch / 远程向量服务 | 对单机本地工具过重，且违背不联网 |
| 会话级 chunk、510 token 窗口 | 会话块过大；窗口无收益 |
| 短轮次阻尼、自适应权重、停用 bigram | 全部为负或零 |
| 语料共现自动词表 | 噪声冲垮锚点层 |
| 交叉编码器重排默认开启 | 质量 +7pt R@1，但 1.8 s/查询，违反延迟预算 |
| 日期过滤 | 机制有效但仅 4 条同日金标，证据不足以默认开启 |
| 按文档语言切索引 | 文献与自测都指向更差 |
| 翻译式查询扩展 | 错误传播、延迟高，不适合每次工具调用 |

## 成本

| 指标 | 实测 |
|---|---|
| 安装增量（依赖 + 模型） | ≈189 MiB |
| 索引体积（1,312 turn） | SQLite 8.2 MB + 向量 2.0 MB |
| 全量重建 | 26–28 秒（CPU） |
| 单会话增量 | ≈3 秒 |
| 单次检索 | 约 25 ms（含摘录/MMR；embedding 约 2 ms） |
| 首次调用冷启动 | ≈1.8 秒（加载模型） |

完整的方法、协议细节与可信度说明见 **[docs/TECHNICAL-REPORT.md](docs/TECHNICAL-REPORT.md)**，
验证方案见 **[docs/VALIDATION.md](docs/VALIDATION.md)**。

## 局限

- **跨语言召回弱**：英文问中文内容时约 0.12 nDCG（已按语言切到稠密通道）；同语言检索好得多（0.30–0.44）。
- **纯改写查询不稳定**：带专名、命令、标识符的查询召回最好；这是测量结果，不是猜测。
- 索引是派生缓存，可随时重建；不回写你的会话。
- 只在单机单用户、单一 DSH 版本上验证过；不支持多用户或远程部署。
